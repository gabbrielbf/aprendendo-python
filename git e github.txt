Pull Request:
    É um tipo de solicitação formal para integrar (mesclar/merge) alterações de código feitas em ramo paralelo (branch) ao ramo principal 
    de um projeto (como a main ou master).

 Para que serve?
    Permite que outros desenvolvedores analisem o código, façam perguntas, 
    sugiram melhorias e detectem bugs antes que as alterações afetem o projeto principal.

    Automação e Testes (CI/CD): Dispara rotinas automatizadas que verificam se o novo código passa nos testes, 
    segue os padrões de estilo e não quebra a aplicação.

    Funciona como um registro centralizado que explica o que foi alterado, 
    por que foi alterado e quais decisões foram tomadas pela equipe.

Open Source:
    é um modelo de desenvolvimento de software em que o código-fonte é disponibilizado 
    publicamente para qualquer pessoa visualizar, modificar, aprimorar e redistribuir gratuitamente.

    um bom exemlo que temos de projeto Open Source é o React: https://github.com/react/react

 Os Princípios Fundamentais:
    Transparência: Qualquer pessoa pode inspecionar como o software funciona por dentro.

    Colaboração: Desenvolvedores do mundo inteiro podem contribuir corrigindo bugs, adicionando funcionalidades ou melhorando a segurança.

    Liberdade de Uso e Adaptação: O código pode ser adaptado para atender às necessidades específicas de uma pessoa ou empresa.

    Licenciamento Aberto: O projeto é regido por licenças (como MIT, Apache ou GPL) que garantem essas liberdades e definem regras de redistribuição.

Issue:
    é um registro usado em plataformas de hospedagem de código (como GitHub, GitLab e Bitbucket) para organizar, 
    discutir e rastrear tudo o que precisa ser feito ou corrigido em um projeto de software.

    Se a Pull Request (PR) é o código pronto que queremos entregar, a Issue é o debate ou a demanda que vem antes do código.

 Como uma Issue se conecta com uma PR(Pull Request)?
    O fluxo padrão de desenvolvimento une os dois conceitos:

    Alguém abre uma Issue: "A tela de login está travando ao digitar a senha".

    Um desenvolvedor assume a Issue e cria um ramo (branch) para resolver o problema.

    Quando a solução está pronta, ele abre uma Pull Request (PR) apontando para a Issue original (ex: "Fixes #42").

    Assim que a PR é aprovada e mesclada (merged), a Issue é fechada automaticamente.
